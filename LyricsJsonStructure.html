File naming

File names may be any text descriptive of the contents, but the file name needs to end in the string _Lyrics. Examples are Yitro_Lyrics.json and Zachor Maftir_Lyrics.json. For sample files included in the website, the name is used to access appropriate resources. User files only need names shared as filename.json for the trope sequence and filename_Lyrics.json for the lyrics for the part.

Lyrics structure

The Lyrics JSON file has the structure displayed at left. Each lyric word is represented by Hebrew characters and possibly punctuation, vowels, and trope marks associated with the key "hebrew", with English transliteration associated with the key "translit".

The colors in the example indicate common levels of grouping within the JSON object. The full-width colored bands make the nested structure visible: each word-array block is enclosed by the delimiters for its line, and the line objects are enclosed by the delimiters for the overall "lines" array.

Pocket Torah compatibility

The title can be any string; however, if the files are compatible with Pocket Torah, the title must end in -PT. Line names can also be any string, but for Pocket Torah compatibility they must match the Book, Chapter, and Verse of the source text.

In the example at left, the verses are from chapter 25 of Deuteronomy. The title references the parsha as Ki Teitzei, but that part of the title can be any meaningful string as long as the -PT ending is preserved.

Lines and words

Words do not have an identifier similar to the lines and are added to the line array as necessary. Additional line objects accommodate the line count for the portion.

The portion does not have to be a Torah source, but such text cannot be Pocket Torah compatible and there may be no associated audio available for the selection. The Lyrics file can still define the displayed Hebrew text of a reference, such as a prayer text from the Siddur.
